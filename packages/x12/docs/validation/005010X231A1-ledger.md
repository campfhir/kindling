# X12 999 Implementation Acknowledgment (005010X231 / 005010X231A1): structure checked against free public sources

Researched 2026-10-30. Every URL below was downloaded and its text checked (PDFs converted with `pdftotext -layout`, HTML stripped to text).
Sources are limited to x12.org, CMS, Medicare MAC and state Medicaid/state agency publications. No vendor or blog pages are used.
Pages found by search but **not used** because they are vendor or non-public-agency pages: Stedi, Availity, PilotFish, EDIFabric, TIBCO, TrueCommerce, Magellan of Louisiana, Optum Maryland, GuideWell/Florida Blue, BCBSM, BCBSNC.

**Main limitation.** No free source I could reach prints the TR3's segment table with **Max Use** and **Loop Repeat** counts, or with element **type / min-max** for most 999 elements. X12 Glass is behind a paid license (noted by the maintainer, 2026-10-30), so it is not a free public source for this ledger. The one state guide that has these columns, Ohio Department of Aging `ODA999-5010.pdf`, returned HTTP 404. See Section 7. Usage (R/S) and order are well confirmed. Repeat counts are given only where a source states them or a sample proves them.

**Order check.** The DC list in §A.2 gives the same order: "ST, AK1, AK2, IK3, CTX – Segment Context, CTX – Business Unit Identifier, IK4, CXT [sic] – Element Context, IK5, AK9, SE". In the X12EX sample the segment context CTX comes before the business unit CTX, and the business unit CTX before IK4. This matches IN and WI.

**Nesting (from IN loop labels and WI loop IDs).** Loop 2000 = AK2 … IK5. Loop 2100 = IK3 + its two CTX segments, inside 2000. Loop 2110 = IK4 + Element Context CTX, inside 2100.

**Situational rules, quoted:**
- Loop 2000 AK2 (WI): *"Information in this loop is required when an error is present in a transaction set contained in the functional group to which this 999 transaction set is responding. If not required by this implementation guide, the information may be provided at the sender's discretion but cannot be required by the receiver."* IN: *"If there are no errors at the transaction set level, this segment is not returned"* (IHCP practice). X12EX and CMSACK show AK2 loops with `IK5*A` for clean transaction sets.
- 2100 Segment Context CTX (WI): *"Required when the error identified in this IK3 loop was triggered by a situational requirement of the implementation guide and the error occurs at the segment level."*
- 2100 Business Unit Identifier CTX (WI): *"Required when the error reported in this IK3 loop is within a business unit and the business unit identifier is known by the submitter of the 999."*
- 2110 IK4 (WI): *"required when the error in the segment described in the IK3 segment applies to a data element and the location of the data element containing the error can be identified by the submitter of the 999."*
- 2110 Element Context CTX (WI; RFI2366 quotes the same rule): *"Required when the error identified in this IK4 loop was triggered by a situational requirement of the implementation guide and the error occurs at the element level. If not required by this implementation guide, do not send."*
- RFI1311: *"The CTX is used when an error reported in an IK3 or IK4 segment is ambiguous without further information."*

## 4. 005010X231 vs 005010X231A1 (errata)

CMSACK slide 20, "999 Errata – Proposed Errata Content" (Sept. 2010), quoted:
- "Additional note added to 2100 AK2/IK303"
- "Change to CTX segments – New notes added to CTX04, Situational rule change for CTX06, CTX06-2 changed from Situational to Not Used"
- "Change to 2000 IK5 segment – Added code value to IK502, and changed IK5"
- "Change to situational rule for TA1 segment – TA1 is no longer required when an interchange is rejected"

So **the loop and segment structure is the same** between X231 and X231A1 in every source. The differences are notes, situational rules, CTX06-2 usage and one added IK502 code. **Which IK502 code was added is not confirmed** (WI's A1 list contains I5 and I6, but no source names the addition). The wording of the CTX06 rule change is also not confirmed.

Corroborating sample: WI's (X231-era) example of the same scenario carries a CTX06 in the segment context CTX; X12EX (A1) has none. This fits the CTX06 rule change, but the link is **my inference**.
