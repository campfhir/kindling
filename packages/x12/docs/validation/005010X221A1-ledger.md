Sources are limited to x12.org, CMS, Medicare MAC and state publications. One health-plan guide (AGP) is used only as a cross-check for TR3 page order. No blog pages are used.
The full 005010X221A1 TR3 is sold by X12 and was **not** consulted. X12 Glass needs a paid license, so it was not used.

Usage codes: **R** = Required, **S** = Situational, **N/U** = Not Used (XA1 prints `N/U`).
"Max use" is XA1's `Min. Max.` column on the segment row. "Loop (repeat)" is XA1's `Loop Repeat` column, which is printed only on the row that starts a loop.
**Names:** XA1 prints Medicare descriptions, some of them shortened (e.g. "Claim Level Data" for CLP). The name column uses the wording that ISDH, MTF, UT, AGP and the MAC guides print, which matches the TR3 page names those guides cite. Where XA1 words a name differently, its wording is shown in brackets.
**TR3 page** (in Sources): the TR3 page number that the companion guides print for the segment row. When several guides agree, the guides are listed. Page numbers are useful as an independent check of segment order.

## 1. Hierarchy

```
ST
  BPR, TRN, CUR, REF(EV), REF(F2), DTM(405)          header, no loop
  1000A Payer Identification  (1)    N1(PR) N3 N4 REF PER(CX) PER(BL) PER(IC)
  1000B Payee Identification  (1)    N1(PE) N3 N4 REF RDM
  2000 Header Number          (>1)   LX TS3 TS2
    2100 Claim Payment Information (>1)  CLP CAS NM1… MIA MOA REF… DTM… PER AMT QTY
      2110 Service Payment Information (999)  SVC DTM CAS REF… AMT QTY LQ
  PLB                                   summary, no loop
SE
```

Evidence:
- Loop IDs and repeats come from XA1: 1000A `1`, 1000B `1`, 2000 `>1`, 2100 `>1`, 2110 `999`. MTF Table 4 gives the same loop repeats and calls the sections HEADER, DETAIL and SUMMARY. PLB has the loop column `-------` (no loop) in XA1 and sits under SUMMARY in MTF. ISDH uses loop "N/A" for PLB.
- Loop names come from MTF and ISDH: "LOOP ID – 1000A PAYER IDENTIFICATION", "1000B PAYEE IDENTIFICATION", "2000 HEADER NUMBER", "2100 CLAIM PAYMENT INFORMATION", "2110 SERVICE PAYMENT INFORMATION" (MTF). AGP and NOV have the same headings.
- The X12 examples follow this order: header, 1000A, 1000B, `LX`, then one `CLP` per claim, each followed by its 2110 `SVC` groups, then `SE`. X2 shows several 2100 loops under one LX.

### How the repeated segment IDs are told apart

- **1000A PER** (three positions, each max 1): PER01 `CX` = Payer Business Contact (S); `BL` = Payer Technical Contact (R); `IC` = Payer Web Site (S, PER02 N/U, PER03 `UR` R, PER05–PER08 N/U). Sources: XA1, UT and MN. Every X12 example that has all three PERs sends them in the order `CX`, `BL`, `IC`. NV's SNIP edits name them `PER_CX` and `PER_BL`.
- **2100 PER** has a single position, Claim Contact Information, with PER01 `CX` and max 2. It can only be told apart from the 1000A business contact by its loop.
- **2100 NM1**, in TR3 order: `QC` Patient (R), `IL` Insured, `74` Corrected Patient/Insured, `82` Service Provider, `TT` Crossover Carrier, `PR` Corrected Priority Payer, `GB` Other Subscriber. NV SNIP: "2100 NM101="PR" is not used when 2100 NM101="TT" is used".
- **2100 REF**: Other Claim Related Identification (REF01 `1L, 1W, 28, 6P, 9A, 9C, BB, CE, EA, F8, G1, G3, IG`) vs Rendering Provider Identification (other qualifiers, list not confirmed). X8a sends a REF with REF01 `TJ` after the `1L`/`CE` REFs. `TJ` is not in the Other Claim list, so it fits the Rendering Provider Identification position. That placement is an inference.
- **2100 DTM**: `232`/`233` Statement From/To (max 2), `036` Coverage Expiration, `050` Claim Received.
- **2110 REF**: `LU, 1S, APC, RB, BB, E9, G1, G3` Service Identification; `6R` Line Item Control Number; `HPI, SY, TJ, 1C, 1G, 0B, 1A, 1B, 1D, 1H, 1J, D3, G2` Rendering Provider Information; `0K` HealthCare Policy Identification. `G1` is listed only in Service Identification, and `TJ`/`D3` only in Rendering Provider Information.
- **Header REF**: `EV` Receiver Identification, then `F2` Version Identification.

The full sequence comes from AGP (cross-check only). Each page that NV, NOV/CGS, VA, WA, MD or UT print matches it, except the disagreements noted below.

The X12 examples show the same order inside 2100: CAS (X6) → NM1 QC → IL → 74 → 82 (X8a–c) → MOA (X5a–c) → REF → DTM 232/233 → DTM 050 → PER CX (X4, X6) → AMT AU → QTY CA (X6). ## 3. Element tables

All rows come from the XA1 5010A1 column unless noted. **Names are XA1's Medicare descriptions**; where a guide prints the TR3 industry name it follows in brackets. 2. **2100 NM1 Insured Name (`IL`) element table.** XA1 gives the segment row only (S, 1, values `N/A`). Only NM102 `1, 2` (MN) and NM108 `MI` (X8a–c) are seen.

   - 1000A N103 (only `XV` is seen);
