# Validation records

How the HL7 facts in `@campfhir/hl7` were checked, and against what.

- [`v2.3-segment-ledger.md`](v2.3-segment-ledger.md) and
  [`v2.3.1-segment-ledger.md`](v2.3.1-segment-ledger.md): every field of every segment of the
  version compared with hl7.eu, the Caristix reference and HAPI, with the date the sources were
  read, the value decided for each attribute, every contradiction between the sources, what our
  class implements (its own class or an older version's re-exported), and which tests cover it.
  Generated by `codegen/validate/ledger.mjs <version>`; hand-written decisions are in
  `codegen/validate/ledger-v23-notes.json` and `ledger-v231-notes.json`.
- [`v2.3-message-ledger.md`](v2.3-message-ledger.md) and
  [`v2.3.1-message-ledger.md`](v2.3.1-message-ledger.md): every message structure of the version
  rendered in the standard's abstract syntax from our schema, the hl7.eu chapter tables (v2.3 only;
  hl7.eu publishes no 2.3.1 chapters), Caristix and HAPI, compared by shape, with the deliberate
  modelling decisions and their reasons dated in `codegen/validate/message-notes.json`. Generated
  by `codegen/validate/message-ledger.ts <version>`.
- [`v2.3-hl7eu-sweep.md`](v2.3-hl7eu-sweep.md) and
  [`v2.3-hapi-crosscheck.md`](v2.3-hapi-crosscheck.md): the first sweeps (2026-10-19), superseded
  by the ledger and kept for the history of the decisions.

## The rule

hl7.eu is the authoritative source for a segment's field table. When the sources disagree on a
field's type, repeat, usage or length, hl7.eu's value is used unless Caristix and HAPI agree with
each other against it; then the two of them win. Whichever way it goes, the disagreement is written
in the field's row of the ledger with the value each source gave, so nobody has to look it up
again. When hl7.eu contradicts itself (its segment index page against the printed chapter text,
as for NSC), the printed text wins and the decision is recorded in the notes file with its date.

## Refreshing the ledgers

```sh
codegen/validate/fetch-sources.sh v2.3.1 /tmp/hl7-sources/v2.3.1   # hl7.eu pages, Caristix JSON, HAPI classes
node codegen/validate/ledger.mjs v2.3.1 /tmp/hl7-sources/v2.3.1     # writes v2.3.1-segment-ledger.md
node codegen/validate/ledger.mjs v2.3.1 /tmp/hl7-sources/v2.3.1 --fix-spec   # also corrects codegen/spec/v2.3.1-segments.json
node codegen/validate/ledger.mjs v2.3.1 /tmp/hl7-sources/v2.3.1 --adopt OM1,PRC   # seeds the version's spec for segments that get their own class
```

The message ledger reads the Caristix trigger-event JSON, HAPI's message and group classes with its
event map, and (for v2.3) the hl7.eu chapter pages:

```sh
npx tsx codegen/validate/message-ledger.ts v2.3 --caristix /tmp/caristix/v2.3 --hapi /tmp/hapi23/message /tmp/hapi23/group /tmp/hapi23/2.3.properties --hl7eu /tmp/hl7eu-v23
npx tsx codegen/validate/message-ledger.ts v2.3.1 --caristix /tmp/caristix/v2.3.1 --hapi /tmp/hapi231/message /tmp/hapi231/group /tmp/hapi231/2.3.1.properties
```

After `--fix-spec`, regenerate the generated classes (delete them and run
`npx tsx codegen/generate-segments.ts --version v2.3.1`, then `pnpm test:positions`) and run the
ledger again. A version whose segment re-exports an older class is checked against that class; when
the version's table differs, `--adopt` copies the table into the version's spec with the decided
values, the re-export stub is deleted and the class generated (a hand-written base class gets a
hand-written subclass instead, as `src/segments/v2.3.1/RXA.ts` does).
